# Repository workflow

## Authority

- `main` is authoritative for Sacratus lore and repository instructions.
- Lore on `main` outside `working/` is canon, including lore in subdirectories.
- `AGENTS.md` and repository configuration are authoritative operational instructions, not lore.
- `README.md` is human-facing navigation only; it does not establish canon or policy.
- `working/` is explicitly non-canonical scratch space.
- Chat, model memory, brainstorming, and README summaries are context only when they conflict with merged canon.
- Before asserting established lore, read the relevant canonical files.
- Unmerged PRs and chat decisions are not canon.

## Canon statuses

Use these labels when needed:

- **LOCKED** — established; revise only with explicit user direction.
- **PROVISIONAL** — current answer, still subject to revision.
- **OPEN** — undecided; do not resolve silently.
- **UNKNOWN IN-UNIVERSE** — deliberately unresolved; do not invent an answer.
- **REJECTED** — discarded; do not reintroduce unless explicitly reconsidered.

A status may apply to a fact, date, interpretation, section, or topic. The status itself is canonical.

## Document roles

Use `README.md` to navigate, then read the most specific relevant canon. Detailed subjects should have one primary canonical home; summaries elsewhere should stay concise.

For Palatinae material:

- `overview.md` — what the Chapter is.
- `history.md` — how and why it became that.
- `timeline.md` — when events happened.
- `constantines.md` — holders of the Constantinian office, their careers, motives, and reigns.
- `organization.md` — structure, offices, companies, recruitment, manpower, and institutional mechanics.
- `culture.md` — beliefs, traditions, memory, religion, and lived culture.
- `heraldry.md` — colors, markings, armor provenance, and visual traditions.

When moving or splitting canon, preserve meaning and status, remove competing detailed copies, and update navigation/links when needed. Do not create files merely because a category could exist.

## Consistency and lore review

Do not silently reconcile genuine conflicts between canonical files. First check whether differences reflect status labels, different eras, perspective, or summary versus detail. If a real conflict remains, surface it unless established canon or an explicit user decision resolves it.

When developing or revising lore, apply a lightweight review for:

- internal, character, and institutional continuity;
- Warhammer 40,000 compatibility in chronology, scale, institutions, technology, Warp behavior, and Astartes norms;
- tone and thematic continuity;
- unnecessary exceptionalism or added "specialness";
- accidental resolution of `OPEN`, `PROVISIONAL`, or `UNKNOWN IN-UNIVERSE` material;
- knock-on effects elsewhere in canon.

Treat issues as hard conflicts, soft tensions, open choices, or deliberate revisions. Do not manufacture objections when an idea fits cleanly. Verify external 40k lore when materially uncertain or edition-sensitive.

## AI GitHub workflow

AI actions performed through the user's GitHub account must remain distinguishable from human actions.

- Never push AI-generated changes directly to `main`; use a branch and PR.
- AI-authored PR bodies, issue text, review comments, and similar outward-facing prose must begin with a clear AI attribution such as `AI-generated by ChatGPT.`
- AI-generated commit messages must include:

  `AI-Generated-By: ChatGPT`

- Do not use non-attributable actions such as approvals, merges, or reactions merely to express the user's judgment; perform them only when explicitly requested.
- PR descriptions should summarize meaningful canon additions, removals, reorganizations, and status changes.
- Do not treat an unmerged PR as accepted canon.

## Working material

`working/` may contain unresolved ideas, alternatives, rejected concepts, continuity notes, and discussion summaries. It may change freely without implying canon changes.

Merged canon overrides `working/`. Persistence in `working/` does not promote an idea. Moving material from `working/` into canonical lore requires user review through a PR.
